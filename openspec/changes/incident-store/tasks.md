## 3. Store port and repository

- [ ] 3.1 In `yubarta/domain/ports.py`, replace `SignalStore` with an `IncidentStore` `Protocol`: `create(signal: Signal, target_name: str) -> Incident`, `transition(incident_id: str, to_state: IncidentState, expected_version: int, lease_generation: int) -> Incident`, `record_attempt(incident_id: str, remediation_name: str, approval_status: AttemptApproval = AttemptApproval.not_required) -> RemediationAttempt`, `resolve_approval(attempt_id: str, approval_status: AttemptApproval, approved_by: str | None) -> RemediationAttempt`, `complete_attempt(attempt_id: str, outcome: AttemptOutcome, evidence: dict | None) -> RemediationAttempt`, `get(incident_id: str) -> Incident | None`, `list_by_target(target_name: str) -> list[Incident]`, `list_recent(limit: int) -> list[Incident]`
  - Partially done: `SignalStore` is gone and `IncidentStore` exists, but `transition` is missing the `expected_version` and `lease_generation` parameters.
- [ ] 3.2 Add `yubarta/infra/db/unit_of_work.py`: a Postgres-scoped Unit of Work per [ADR-0007](../../../records/adr/0007-postgres-scoped-unit-of-work.md) that owns the transaction boundary and commits or rolls back as one, so no store method calls `session.commit()` on its own. It SHALL NOT appear in the `IncidentStore` Protocol signature: the port stays free of SQLAlchemy
- [ ] 3.3 In `yubarta/infra/db/repository.py`, replace the placeholder `SqlAlchemySignalRepository` with `SqlAlchemyIncidentStore` implementing `IncidentStore`: `create` inserts `incidents` idempotently on `signal_id` conflict (returns the existing row instead of erroring)
  - Done except that it commits directly instead of going through the Unit of Work from 3.2.
- [ ] 3.4 Implement `transition` as a conditional update: within one transaction, `UPDATE incidents SET state = :to_state, version = version + 1, updated_at = now() WHERE id = :incident_id AND version = :expected_version AND lease_generation = :lease_generation`, inserting the `incident_transitions` row (from current state to `to_state`) in the same transaction. Zero rows updated means the write was rejected: re-read the row to distinguish a moved version (raise `ConcurrentModificationError`) from a superseded lease (raise `StaleLeaseError`), and raise `IncidentNotFoundError` if no row exists at all. No `SELECT ... FOR UPDATE`
  - **Currently implemented the opposite way**: the existing `transition` takes a row lock with `.with_for_update()` and has no version or lease guard. [ADR-0006](../../../records/adr/0006-three-mechanism-concurrency-model.md) rejects that by name. Replace it.
- [ ] 3.5 Implement `record_attempt`: derive the idempotency key from `(incident_id, remediation_name, attempt_sequence)`, persist `approval_status` (default `not_required`) on the pre-execution row, insert before returning. Any existing row with that key rejects the insert; raise `DuplicateAttemptError` carrying the existing attempt, so the caller can distinguish an attempt still in flight (no outcome recorded, the side effect may or may not have happened) from one already completed (outcome recorded, result readable). Never let the underlying integrity error escape the store
  - Partially done: it raises `DuplicateAttemptError` only for the in-flight case, carries just the key rather than the attempt, and lets a completed-key collision reach Postgres as an `IntegrityError`.
